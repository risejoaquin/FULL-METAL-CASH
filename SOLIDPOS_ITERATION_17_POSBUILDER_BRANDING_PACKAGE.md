# SolidPOS Iteration 17 — PosBuilder Foundation + Tenant Branding Package

## Status

Prepared for local validation.

## Objective

Start the real PosBuilder surface and define a tenant branding package that can be generated, validated, and consumed by PosCore/WPF without hardcoding tenant brand names, app names, receipt text, or color metadata in the UI flow.

## Scope implemented

- New PosBuilder WPF project: `src/PosBuilder/SolidPOS.PosBuilder.Wpf`.
- Tenant branding package domain contract.
- Branding package generation service.
- JSON package store.
- CLI commands for package creation, validation, and inspection.
- PosBuilder WPF self-test.
- PosCore WPF branding consumption in self-test.
- Branding tab in PosCore WPF shell.
- Unit tests for branding package creation, validation, and load/save roundtrip.
- Validation script for the full local flow.


## Architectural decision

The tenant branding package is generated by PosBuilder and consumed by PosCore/WPF through the application/domain contracts. The WPF UI reads brand metadata through ViewModels; it does not own tenant branding rules or package validation logic.

## Out of scope

- Real asset upload pipeline.
- Velopack package signing.
- Remote update distribution.
- Multi-theme editor.
- Cloud persistence of branding packages.

Those belong to Iteration 18.
